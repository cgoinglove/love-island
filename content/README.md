# content/

**여기가 원고다.** 코드를 안 열고 이 폴더만 고쳐서 커밋하면 사이트 내용이 바뀐다.

| 파일 | 무엇 |
|---|---|
| `profile.json` | 이름 · 연락처 · 포트폴리오 주소 · 사진첩 |
| `../public/photos/` | 실제 사진 파일. `profile.json` 의 `src` 에 `/photos/파일명.jpg` 로 적는다 |

## 왜 DB 가 아닌가

소개와 사진은 **거의 안 바뀌고, 바뀔 땐 본인이 바꾼다.** 그런 원고에 DB 를 붙이면
관리 화면·인증·마이그레이션이 따라오는데, 정작 얻는 건 "커밋 없이 고칠 수 있다"뿐이다.
git 히스토리가 곧 변경 이력이 되는 게 이 규모에선 더 낫다.

방명록은 반대다 — 남이 쓰고, 자주 바뀌고, 커밋할 수 없다. 그래서 그건 Postgres 에 있다.

## 사진 넣기

```
1. public/photos/ 에 이미지를 넣는다      (예: public/photos/desk.jpg)
2. profile.json 의 photos 에 { "id": "desk", "src": "/photos/desk.jpg", "tint": "#f6c9a8" } 를 넣는다
3. 커밋
```

`caption` 과 `when` 은 **안 적어도 된다.** 안 적으면 화면에서 그 줄이 통째로 빠진다 —
사진만 걸고 싶을 때 억지로 한 줄씩 붙이는 게 더 군더더기다.

⚠ **HEIC 는 안 된다.** 사파리 말고는 못 읽어서 대부분의 방문자에게 깨진 이미지로 보인다.
그리고 폰에서 바로 꺼낸 4~7MB 짜리를 그대로 올리면 사진첩 한 번 여는 데 수십 MB 를
내려받는다. 긴 변 1600px · JPEG 로 줄여서 넣는다:

```bash
sips -s format jpeg -s formatOptions 80 -Z 1600 원본.HEIC --out public/photos/이름.jpg
```

원본은 `.originals/` 에 둔다(gitignore 됨). 배포에는 축소본만 올라간다.

`src` 를 안 적으면 `tint` 색 카드가 대신 나온다. 자리를 채우려는 게 아니라,
사진이 아직 없어도 레이아웃이 안 무너지게 하려는 것이다.

## 한국어와 영어

글이 들어가는 자리는 **둘 중 아무렇게나** 적으면 된다.

```jsonc
"tagline": "걸어서 갈 수 있는 이력서",                              // 한 줄 — 모든 언어가 이걸 쓴다
"tagline": { "ko": "걸어서 갈 수 있는 이력서", "en": "a résumé you can walk through" }
```

한 줄로 적으면 `/en` 에서도 그 값이 그대로 나온다. **번역을 강요하지 않는 게 요점이다** —
원고는 당신 것이라 없는 영어를 코드가 지어낼 수 없고, 안 적었다고 화면이 비어서도 안 된다.
영어를 넣고 싶은 항목만 갈라 적으면 된다.

기술 스택(`stack`)은 언어를 안 탄다. `TypeScript` 를 번역할 일은 없으니까.

지금 들어 있는 영어는 **예시 원고의 번역**이다. 실제 내용으로 바꿀 때 영어도 같이
바꾸거나, 필요 없으면 `{ "ko": … }` 만 남기면 된다.

## 잘못 적으면

`shared/content.ts` 의 zod 스키마가 **빌드 때** 잡는다. 오타 난 JSON 이 조용히
빈 화면으로 나가는 대신 빌드가 깨진다 — 원고는 조용히 틀리는 게 가장 나쁘다.

`shared/content.test.ts` 는 한발 더 나가서 **어느 언어로 펴도 빈 글이 없는지** 본다.
빈 칸은 오타처럼 조용히 지나가고, 배포하고 한참 뒤에야 눈에 띈다.
