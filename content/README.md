# content/

**여기가 원고다.** 코드를 안 열고 이 폴더만 고쳐서 커밋하면 사이트 내용이 바뀐다.

| 파일 | 무엇 |
|---|---|
| `profile.json` | 이름 · 연락처 · 경력 · 사진첩 |
| `../public/photos/` | 실제 사진 파일. `profile.json` 의 `src` 에 `/photos/파일명.jpg` 로 적는다 |

## 왜 DB 가 아닌가

경력과 사진은 **거의 안 바뀌고, 바뀔 땐 본인이 바꾼다.** 그런 원고에 DB 를 붙이면
관리 화면·인증·마이그레이션이 따라오는데, 정작 얻는 건 "커밋 없이 고칠 수 있다"뿐이다.
git 히스토리가 곧 변경 이력이 되는 게 이 규모에선 더 낫다.

방명록은 반대다 — 남이 쓰고, 자주 바뀌고, 커밋할 수 없다. 그래서 그건 Postgres 에 있다.

## 사진 넣기

```
1. public/photos/ 에 이미지를 넣는다      (예: public/photos/desk.jpg)
2. profile.json 의 해당 photo 에 "src": "/photos/desk.jpg" 를 추가한다
3. 커밋
```

`src` 를 안 적으면 `tint` 색 카드가 대신 나온다. 자리를 채우려는 게 아니라,
사진이 아직 없어도 레이아웃이 안 무너지게 하려는 것이다.

## 잘못 적으면

`shared/content.ts` 의 zod 스키마가 **빌드 때** 잡는다. 오타 난 JSON 이 조용히
빈 화면으로 나가는 대신 빌드가 깨진다 — 원고는 조용히 틀리는 게 가장 나쁘다.
