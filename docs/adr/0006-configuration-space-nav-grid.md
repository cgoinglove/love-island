# 0006. 네비 그리드를 configuration space 로 정의한다

## 상태

채택 (2026-08)

## 맥락

캐릭터가 우체통에서 오두막으로 걸어가다 나무 사이에 끼어서 영원히 도착하지 못했다.
경로는 멀쩡히 나오는데(A* 가 웨이포인트를 4개 돌려줬다) 몸이 안 지나갔다.

원인은 **계획과 이동이 서로 다른 기준을 본 것**이었다:

| | 무엇을 봤나 |
|---|---|
| `findCellPath` (A*) | 칸 하나가 통행 가능한가 — **점 판정** |
| `stepPlayer` | 중심 + 반지름 0.35m 원주 4점이 전부 통행 가능한가 — **원 판정** |

칸이 0.5m 이므로 A* 는 나무 두 그루 사이의 0.5m 틈을 "길"로 봤고,
지름 0.7m 인 몸은 거기 끼었다. 도착 판정이 안 서니 `onInteract` 도 안 불렸다.

유닛 테스트는 전부 통과하고 있었다. 손으로 그린 ASCII 맵에는 그런 틈이 없었으니까.

## 결정

**마스크의 의미를 "여기 땅이 있다"에서 "몸의 중심이 여기 올 수 있다"로 바꾼다.**
즉 캐릭터 두께가 이미 반영된 configuration space 로 굽는다.

```
buildNavGrid(spec, isPassable, radius)
  1단계: 칸마다 isPassable(중심)  → 점 마스크
  2단계: 칸마다 중심+원주 8방향이 전부 점 마스크에서 통행 가능한가 → 최종 마스크
```

그리고 계획과 이동이 **같은 배열**을 보게 한다:

- `findCellPath` → `walkable[cell]`
- `stepPlayer` → `canStandAt(x, z)` = `walkable[cellOf(x, z)]`
- `hasLineOfSight` → 같은 함수

`canStandAt` 은 더 이상 반지름을 받지 않는다. 두께는 마스크에 한 번만 먹인다 —
두 번 먹이면 실제보다 두 배 뚱뚱한 몸이 되어 멀쩡한 길이 막힌다 (이것도 한 번 겪었다).

## 결과

- 어긋남이 구조적으로 불가능해졌다. A* 가 돌려준 칸은 정의상 설 수 있는 자리다
- 통행 가능 영역이 나무 주변에서 0.35m 씩 줄었다. 나무에 몸을 비빌 수 없게 됐는데,
  어차피 비빌 수 있으면 안 되는 거였다
- 굽는 비용이 칸당 9번의 **배열 조회**로 늘었다. 160x160 이면 23만 번, 체감 0ms.
  값비싼 `isPassable`(지형 + 장애물 74개)은 여전히 칸당 한 번만 부른다
- 테스트 그리드도 같은 의미론으로 구워야 한다. `buildNavGrid(spec, fn)` 처럼
  반지름을 빼면 점 마스크가 나오고, 그건 프로덕션과 다른 세계다

## 이 버그가 남긴 것

**유닛 테스트만으로는 못 잡는 종류의 버그가 있다.**
`game/player/island-nav.test.ts` 는 실제 섬에서 랜드마크 30쌍을 **직접 걸어본다** —
경로를 받아 `stepPlayer` 를 1초에 60번씩 돌려 도착하는지 본다.
손으로 그린 맵이 아니라 진짜 데이터를 쓰는 것, 그리고 "경로가 나온다"가 아니라
"실제로 도착한다"를 검증하는 것. 둘 다 없었으면 또 놓쳤다.
