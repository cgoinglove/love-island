# 0005. 위치는 WebRTC P2P 로 보내고, 폴링을 폴백으로 남긴다

## 상태

채택 (2026-08). [ADR 0004](0004-presence-over-postgres-instead-of-durable-objects.md) 를 보완한다 — 폐기하지 않는다.

## 맥락

0004 는 "동시 접속이 상시 두 자릿수가 되면 폴링은 더 이상 싸지 않다"고 적어뒀다.
그런데 그 시점을 기다릴 필요가 없었다. **좌표는 서버를 거칠 이유가 없는 데이터다.**

정리하면 이렇다:

- Yjs 는 이 문제와 무관하다. 기획서 §5.1 스스로 플레이어 위치는 awareness(휘발)이지
  CRDT 가 아니라고 못박아 뒀다. Yjs 가 필요한 건 낙서(Y.Array)와 가구(Y.Map)뿐이고,
  둘 다 아직 안 만들었다
- Durable Objects 가 사준 건 "방당 인스턴스 하나 + 브로드캐스트"였다.
  그런데 **좌표가 P2P 로 흐르면 브로드캐스트할 서버 자체가 필요 없다**
- 서버가 할 일은 악수(offer/answer/ICE 후보) 중계뿐이고, 그건 peer 한 쌍당 메시지 몇 개다

## 결정

**WebRTC DataChannel 로 브라우저끼리 직접 좌표를 주고받고, Vercel 은 시그널링만 한다.**

```
① 브라우저 A ──┐
               ├─→ POST /api/presence (Postgres 우편함)   ← 악수할 때만
② 브라우저 B ──┘
                     ↓ 악수 끝
③ A ←──── WebRTC DataChannel (20Hz, 6바이트) ────→ B     ← 서버 안 거침
```

- 시그널링은 **기존 presence 엔드포인트에 얹었다.** 왕복 한 번에 위치 교환 + 악수 중계를
  같이 한다. 전용 통로를 팔 값어치가 없다
- 우편함은 `signal` 테이블. `DELETE ... RETURNING` 으로 읽으면서 지우므로
  같은 메시지를 두 번 받는 일이 없다
- DataChannel 은 `ordered: false, maxRetransmits: 0` — 사실상 UDP 다.
  늦게 온 좌표는 어차피 버려지므로 순서도 재전송도 필요 없다
- 좌표는 16비트 고정소수점으로 양자화해 **6바이트**로 보낸다 (JSON 이면 40바이트쯤).
  정밀도 1mm, 캐릭터 반지름이 35cm 인 게임에 충분하다

### 폴링은 지우지 않았다

**symmetric NAT(모바일 통신망·회사망) 뒤에서는 STUN 만으로 안 뚫린다.** TURN 릴레이가
필요한데 그건 대역폭을 쓰는 거라 무료가 사실상 없다. 경험적으로 연결의 10~20% 가 실패한다.

그래서 0004 의 폴링을 폴백으로 남겼다. 어느 통로로 들어오든 좌표는 **같은 스냅샷 버퍼**에
쌓이므로, 렌더링 쪽은 통로가 뭔지 알 필요가 없고 강등이 저절로 매끄럽다.

보간 지연만 통로에 따라 바꾼다 — P2P(20Hz)는 120ms, 폴링(5Hz)은 320ms.

## 결과

측정치 (브라우저 2개, 둘 다 이동 중, 10초):

| | 0004 (폴링만) | 0005 (P2P + 폴백) |
|---|---|---|
| presence POST | 초당 5회 | **초당 0.6회** |
| 좌표 갱신 | 5Hz | **20Hz** |
| 지연 | 200ms + RTT | RTT (30~80ms) |

- P2P 가 다 붙으면 폴링은 "새 방문자 발견 + 내가 살아있다" 용도만 남아 3초 주기로 늦춘다.
  **서버 호출이 88% 줄었다**
- 배포 대상은 여전히 1개. 외부 서비스 0개
- **TURN 이 없어서 일부 방문자 쌍은 P2P 가 안 붙는다.** 그 경우 조용히 폴링으로 돌아가며,
  느릴 뿐 못 보이지는 않는다. 재협상은 하지 않는다 — 안 뚫리는 네트워크에서 무한 루프가 된다
- P2P 는 mesh 라 연결 수가 n² 이다. 8명까지는 괜찮고 그 위로는 SFU 나 서버 중계가 필요하다
- 낙서 캔버스(Yjs)를 만들 때는 다시 판단해야 한다. stroke 는 **영속 + 병합**이 필요해서
  P2P 만으로는 부족하다 — 그때가 y-webrtc 나 서버 사이드 Y.Doc 을 볼 시점이다
