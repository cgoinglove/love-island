# 0007. 곡률 셰이더는 로컬 공간에서 돈다 — 두 번 데었다

## 상태

기록 (2026-08)

## 맥락

지평선 곡률은 `csm_Position.y` 를 거리²만큼 내리는 한 줄이다. 값싸고 효과가 크지만,
**로컬 공간에서 돈다**는 사실이 두 번 다른 방식으로 물었다.

### ① 인스턴스 스케일이 낙차를 증폭시켰다

산맥을 단위 원뿔 하나로 인스턴싱하면서 `scale.y` 를 최대 92 로 줬다.
로컬 단위로 뺀 14m 낙차가 월드에서 1288m 이 되어 산맥이 통째로 바다 밑으로 사라졌다.
드로우콜을 34개에서 1개로 줄인 최적화가 배경을 통째로 지운 것이다.

식생도 같은 문제를 겪고 있었는데 인스턴스 스케일이 0.8~1.6 이라 오차가 ±40% 였고,
"멀리 있는 나무가 좀 낮네" 정도로만 보여서 아무도 눈치채지 못했다.

### ② 메시를 눕히면 로컬 Y 가 위쪽이 아니다

바다는 `<mesh rotation={[-π/2, 0, 0]}>` 로 눕힌 평면이었다.
그러면 평면의 로컬 +Y 가 월드 -Z 를 가리킨다. 곡률이 `y` 를 내리자
바다가 아래로 꺼지는 대신 **앞뒤로 밀렸고**, 멀리서 보면 바다가 섬 위로 올라와
땅을 덮었다. 걸어가면 그 덮개가 벗겨지는 것처럼 보였다.

지형은 처음부터 `geometry.rotateX()` 로 회전을 버텍스에 구워 넣어서 멀쩡했다.
같은 화면에 두 방식이 섞여 있었고, 멀쩡한 쪽이 있어서 "셰이더 문제는 아니겠지"라고
한동안 잘못 짚었다.

### ④ 회전된 메시는 어떤 보정으로도 안 됐다

스케일 보정까지 넣고도, 회전된 메시(바닥에 눕힌 쪽지, 파라솔 지붕, 선베드 등받이)는
로컬 y 가 월드 아래를 가리키지 않아 낙차가 **옆으로** 갔다. 그림자 수신 좌표(transformed)도
같이 밀려서 그림자가 오브젝트에서 떨어져 나갔다 — "떠 보인다"의 마지막 조각이었다.

## 결정 (최종)

**로컬 보정을 전부 버리고, 월드 공간에서 내린 뒤 클립 공간을 직접 만든다.**

```glsl
vec4 curvedWorld(vec3 localPosition) {
  vec4 world = modelMatrix * vec4(localPosition, 1.0);
  #ifdef USE_INSTANCING
    world = modelMatrix * instanceMatrix * vec4(localPosition, 1.0);
  #endif
  float d = distance(world.xz, cameraPosition.xz);
  world.y -= d * d * uCurvature;
  return world;
}
// csm_PositionRaw = projectionMatrix * viewMatrix * curvedWorld(position);
```

- 월드에서 내리므로 스케일·회전·인스턴싱 전부와 무관하다. 보정 코드가 사라졌다
- `csm_PositionRaw` 는 `transformed` 를 건드리지 않는다 → 그림자 캐스터와 리시버가
  같은(휘지 않은) 공간을 공유해 **그림자가 다시 오브젝트에 붙었다**
- 스케일 나눗셈 해킹(위 ①의 해법)은 폐기

## 결과

- 인스턴스를 어떤 크기로 늘려도 낙차가 일정하다. 산맥·나무·꽃이 같은 곡률을 탄다
- 바다·지형이 같은 방식(구운 회전)이라 둘이 어긋날 수 없다
- 로컬 공간에서 도는 버텍스 셰이더에 월드 단위 값을 빼는 코드는
  **항상** 스케일과 회전을 확인해야 한다. 이 파일이 그 체크리스트다

### ③ 아예 곡률을 안 타는 오브젝트가 있었다

지형·바다·식생은 CSM 으로 곡률을 태웠지만 우체통·비석·액자·파라솔·캐릭터는
평범한 `meshStandardMaterial` 이었다. 그래서 카메라가 멀어질수록 지면만 내려가고
오브젝트는 제자리에 남아 **공중에 떠 보였다**. 사용자가 "디자인이 깨졌다,
공중에 떠 있기도 하다"고 말해준 게 이 버그의 첫 신고였다.

곡률 값을 prop 으로 내려보내는 구조라, 새 오브젝트를 만들 때마다 그걸 받아
넘기는 걸 잊으면 조용히 뜨는 구조였다. 값을 **공용 유니폼 객체**로 바꾸고
`<CurvedMaterial>` 하나만 쓰게 해서 빠뜨릴 여지를 줄였다.

## 이 버그들이 남긴 것

둘 다 타입 체커도 린터도 테스트도 못 잡았다. GLSL 은 컴파일러가 없고,
결과가 "화면이 이상하다"로만 나온다.

그나마 잡을 수 있었던 건 `shoreSync.test.ts` 류의 조잡한 문자열 검사와,
**사람이 화면을 보고 "이상한데?" 라고 말해주는 것**이었다. 후자가 실제로 이 버그를 잡았다.
3D 는 아직 눈이 최종 테스트다.

## 덧붙임 — 다섯 번째 함정: 아무도 셰이더를 안 쓴 경우 (2026-08-07)

월드 공간으로 옮긴 뒤에도 사용자가 두 번 더 "떠 있다"고 말했다. 원인은 셰이더가
아니라 **셰이더를 안 쓴 것**이었다.

- `CharacterModel` 이 처음부터 끝까지 평범한 `meshStandardMaterial` 이었다.
  캡슐 몸통 · 머리 · 귀 · 눈 · 코 일곱 개 전부.
- 발밑 접촉 그림자도 `meshBasicMaterial` 이었다. 빛을 안 받아야 해서
  `CurvedMaterial`(standard 기반) 을 쓸 수 없었고, 그래서 규칙에서 빠져나갔다.
- 목적지 표식 링도 같은 이유로 빠져 있었다.

기본 카메라(거리 24m, 곡률 0.0013)에서 낙차는 **0.75m** — 캐릭터 키의 절반이다.
땅은 내려가고 캐릭터는 안 내려가니 정확히 그만큼 공중에 떴다.

### 그래서 바꾼 것

1. `CurvedBasicMaterial` 을 추가했다. 규칙에 예외를 두는 대신 **규칙을 지킬 수 있는
   도구**를 하나 더 만든다. 빛을 안 받는 것도 갈 곳이 생겼다.
2. 접촉 그림자는 CanvasTexture 를 버리고 셰이더에서 원의 uv 로 직접 그린다.
   맵이 셰이더까지 안 닿으면 **새하얀 원반**이 되는데 실제로 그렇게 나왔고,
   원 하나 그리자고 텍스처를 굽고 `document` 를 건드릴 이유가 없었다.
3. `game/world/materialCoverage.test.ts` 를 만들었다. `game/` 과 `features/` 의
   모든 `.tsx` 를 훑어 기본 머티리얼을 JSX 로 쓴 곳을 찾아내고, 파일명과 함께
   무엇으로 바꿔야 하는지 알려준다.

### 왜 테스트여야 했나

README 에 규칙을 적어뒀고, 그 규칙을 적은 사람이 그대로 어겼다. 이유는 명확하다 —
`<meshStandardMaterial color="red" />` 는 **어느 모로 보나 정상적인 코드**다.
diff 를 봐도, 리뷰를 해도 걸리지 않는다. 잘못됐다는 걸 알려면 "이 프로젝트에는
전역 곡률 셰이더가 있다"는 맥락을 그 순간에 기억하고 있어야 한다.

사람의 주의력에 맡길 수 없는 종류의 규칙은 기계가 지켜야 한다. 규칙을 문서에
적는 것과 규칙을 **실행 가능하게** 만드는 것은 다른 일이고, 세 번 반복된
버그라면 후자를 할 값어치가 있다.
